# Commerce checks (COM)

For online stores. Several rows have no threshold yet: they are measured on the first real case. Rewritten in English from the audit method's commerce outline.

| ID | Title | Question | Where | Pass when | If it fails | Do not touch | Priority | Area | Platforms | Needs | Access |
|---|---|---|---|---|---|---|---|---|---|---|---|
| COM-01 | Payment integration mode | Do card details pass through the site? | Payment settings and the gateway configuration | Cards are entered in the gateway's iframe or after a redirect; test and live keys are separate | Switch to the hosted or redirect mode | Changing the gateway during sales hours | High | security | woocommerce | - | authorized |
| COM-02 | Checkout skimmer check | Is there code stealing cards at checkout? | Checkout HTML, payment plugin files and options | No unknown scripts or card-capturing functions; payment plugin checksums match the release | Open the incident tab at top priority and notify the gateway | Do not clean anything before the snapshot | Critical | security | store | - | authorized |
| COM-03 | Cart and checkout cache exclusion | Are the cart and checkout excluded from the cache? | Cache plugin and CDN | Cart, checkout and account pages are always dynamic | Exclude those routes and the store's session cookies | Turning on page caching without exclusions | High | security | woocommerce | - | authorized |
| COM-04 | Customer data exposure | Is customer data protected? | Customer accounts, exports and orders | No export reachable by URL; sign-in attempts limited; order data visible by role only | Block the files and limit attempts | Deleting orders or customers | High | security | store | - | authorized |
| COM-05 | Orders and stock after a change | Do orders and stock still work after a change? | A test order | A full test order in the gateway's sandbox, then the gateway back in live mode | Fix it before publishing | A test order with a real card; leaving the gateway in test mode | High | security | store | - | authorized |
| COM-06 | Store updates in staging | Are store updates tested first? | Staging | Major store and gateway updates tested in staging with a test order | Roll back with the backup | A store database upgrade in production without a backup | High | security | woocommerce | - | authorized |
| COM-07 | Store account hygiene | Is the store account in the owner's hands? | Store users and apps with permissions | The owner is the client; second factor on; apps reviewed | Transfer ownership; remove old access | Removing the only owner before transferring | High | security | hosted-store | - | authorized |
| COM-08 | Checkout performance | Does checkout load fast on a phone? | PageSpeed on the checkout URL, when it is public | Measured on the first case; no threshold yet | Defer third parties on the checkout | Removing the gateway's script | Medium | speed | store | - | passive |
| COM-09 | Fraud and abuse controls | Is there a brake on fake orders and coupon abuse? | Gateway, coupons and sign-up forms | Measured on the first case; no threshold yet | Add limits and a challenge | Blocking real customers | Medium | security | store | - | authorized |
| COM-10 | Legal pages | Does the store publish the minimum legal pages? | Terms, returns and seller details | The pages the trade requires are present, checked with the owner | Treat it as a separate project | Giving tax advice | Low | security | store | - | passive |
