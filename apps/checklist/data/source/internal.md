# Internal checks (INT)

Active: needs written authorization and administrator access to the dashboard, FTP or the hosting panel. Make a full backup with a tested restore first (INT-07). An indicator of compromise stops the diagnosis and opens the incident tab. Rewritten in English from the audit method's internal list.

| ID | Title | Question | Where | Pass when | If it fails | Do not touch | Priority | Area | Platforms | Needs | Access |
|---|---|---|---|---|---|---|---|---|---|---|---|
| INT-01 | Core integrity | Do the core files match the official release? | Core checksums | No differences and no extra files | Take a snapshot, then reinstall the core from the official package; unknown code opens the incident tab | Do not delete anything before the snapshot | Critical | security | wp | - | authorized |
| INT-02 | Malware patterns | Is there malicious code in the files? | Themes, plugins and uploads | Zero matches beyond known legitimate plugins; zero PHP files in uploads | Take a snapshot and open the incident tab | Do not hand-clean a file that rewrites itself | Critical | security | cms | - | authorized |
| INT-03 | mu-plugins and drop-ins | Is there code that runs silently on every request? | The must-use plugin folder and drop-in files | Only legitimate ones from a known cache or object cache plugin, with headers | Treat unknown ones as an incident | Do not delete the drop-in of a real cache plugin | Critical | security | wp | - | authorized |
| INT-04 | Autoloaded options | Does the database load hidden code or bulk on every page? | The options table, autoloaded rows | Under 800 KB in total; no option holds code | Inspect the largest options; code in an option opens the incident tab | Do not delete core or active plugin options | High | security | wp | - | authorized |
| INT-05 | Administrators and second factor | Who can administer the site? | The users list | Only legitimate administrators, one per person, all with a second factor | Note unknown administrators and treat them as an incident; do not delete them yet | Do not delete users who author content: reassign it | Critical | security | wp | - | authorized |
| INT-06 | Vulnerable and abandoned components | Is any plugin or theme flawed or abandoned? | Installed plugins and themes | No component with an open known flaw; every one maintained | Update or replace | Deleting instead of deactivating; major updates without a backup | High | security | wp | - | authorized |
| INT-07 | Backups include the database and restore | Is there a backup, and has anyone restored it? | The backup plugin or the host's backups | Files and database included; a test restore worked this month; one copy off the host | Make one before any other change | Restoring over production as a test | Critical | security | cms | - | authorized |
| INT-08 | Site Health | Does the CMS report critical problems? | The Site Health screen | No critical items; recommendations noted | Fix the critical items | - | High | security | wp | - | authorized |
| INT-09 | Core, PHP and database versions | Are core, PHP and the database on supported versions? | Site Health information | Core on the latest release; PHP with active support | Plan the upgrades (VEL-04) | Upgrading PHP without testing | High | security | wp | - | authorized |
| INT-10 | Inactive plugins and unused themes | Are components installed but unused? | Plugins and themes | No inactive plugin without a reason; at most three themes | Deactivate first, then remove with a backup | Deleting a plugin that stores data (forms, orders) | Medium | security | wp | - | authorized |
| INT-11 | Dangerous settings | Are risky settings on? | General and discussion settings; config constants | Open registration off; file editing disabled; debug off; comments moderated or closed | Change the settings | - | High | security | wp | - | authorized |
| INT-12 | Permalinks and outgoing mail | Do links and outgoing mail work properly? | Permalink settings and mail sending | Post-name permalinks; mail sent through the domain's authenticated SMTP | Configure SMTP | Changing permalinks without a redirect plan | Medium | security | wp | - | authorized |
| INT-13 | Application passwords and sessions | Are there hidden ways to sign in? | Application passwords and sessions of each user | Only application passwords with a known use; sessions closed at the end | Revoke unknown ones | - | High | security | wp | - | authorized |
| INT-14 | Recently modified files | Is every recent file change explained? | Files modified in the last 30 days | Every change is explained by an update or a logged change | Investigate; an unexplained change opens the incident tab | - | High | security | cms | - | authorized |
| INT-15 | Server rewrite rules | Do the .htaccess files hold only known rules? | .htaccess in the root and subfolders | Only CMS, cache plugin and known custom rules | Remove unknown rules after copying the file | A syntax error returns 500 on the whole site | High | security | wp | - | authorized |
| INT-16 | Config file hardening | Is the config file hardened and clean? | wp-config.php | Hardening constants present; fresh salts; no foreign code | Add the constants with a copy of the file | A syntax error gives a blank page | High | security | wp | - | authorized |
| INT-17 | File permissions | Are file permissions neither open nor too tight? | The file system | Folders 755, files 644, the config file 640 or 600, no 777 | Fix them with a backup | Bulk changes without a backup | Medium | security | cms | - | authorized |
| INT-18 | Child theme | Are theme customisations safe from updates? | The active theme | A child theme is active and the parent is unmodified | Move the changes into a child theme | Editing the parent theme | High | security | wp | - | authorized |
| INT-19 | Third-party code snippets | Does every code snippet have an owner and a purpose? | Snippet plugins | Every snippet has an owner and purpose; none with auto-login, eval or redirects; no non-breaking spaces | Deactivate, do not delete | Deactivating snippets marked as required without reading them; saving an HTML snippet as PHP | Critical | security | wp | - | authorized |
| INT-20 | Cron hooks | Are all scheduled tasks known? | The cron option | Only hooks from the core and recognised active plugins | An unknown hook opens the incident tab | Deleting core hooks | High | security | wp | - | authorized |
| INT-21 | Injected content in posts | Do posts or post meta hold injected scripts? | Posts and post meta | No results beyond legitimate embeds | Clean with a backup; an injection opens the incident tab | Bulk database replacements without a backup | High | security | wp | - | authorized |
| INT-22 | Transients and revisions | How much stale data is in the database? | Options and posts | Counts measured and recorded | Clean up during execution (VEL-11) | - | Low | security | wp | - | authorized |
| INT-23 | Orphan tables | Does every table belong to an active plugin? | Database tables | Every table is used by an active plugin | Export, then drop with the owner's consent | Dropping tables without knowing what they hold | Low | security | wp | - | authorized |
| INT-24 | Spam comments and pingbacks | Is the comment queue under control? | Comments | Queue empty or moderated; pingbacks closed when unused | Moderate the queue and close pingbacks | - | Low | security | wp | - | authorized |
| INT-25 | PHP version, OPcache and memory | Is the PHP setup current and tuned? | The hosting panel | Supported PHP; OPcache on; 256 MB of memory or more | Change it in the panel and run the post-change matrix | Upgrading PHP without the post-change matrix | High | security | cms | - | authorized |
| INT-26 | Access log analysis | Do the access logs show successful requests to paths that should not exist? | Raw access logs | No successful hits on paths that should not exist; brute force answered with 401 or 403 | Investigate; an odd successful access opens the incident tab | - | High | security | cms | hosting-panel | authorized |
| INT-27 | Error log | Does the error log show repeated fatal errors? | The error log | No repeated fatal errors | Fix the cause | - | Medium | security | cms | hosting-panel | authorized |
| INT-28 | Server cron jobs | Are all the server's scheduled jobs known? | Cron jobs in the hosting panel | Only your own jobs (the CMS cron, backups) | A job that fetches remote code opens the incident tab | - | High | security | cms | hosting-panel | authorized |
| INT-29 | FTP, SSH and API tokens | Does every access account have a current owner? | Hosting accounts and tokens | Only accounts and tokens with a current owner | Remove or rotate them | - | High | security | cms | hosting-panel | authorized |
| INT-30 | Mail accounts and forwarders | Are there unknown mailboxes or forwarders? | Mail in the hosting panel | Only known accounts and forwarders | Remove them; an unknown forwarder opens the incident tab | - | High | security | cms | hosting-panel own-mail | authorized |
| INT-31 | Disk usage | Is there room left on the disk? | Hosting quotas | Under 80% used; old backups outside the web root | Move or delete old copies once the last good one is known | Deleting copies without knowing which is the last good one | Low | security | cms | hosting-panel | authorized |
| INT-32 | Staging | Is there somewhere to test before production? | Hosting tools | A staging copy, or a subdomain to clone into | Set one up | Testing major updates in production | Medium | security | cms | - | authorized |
| INT-33 | Elementor inventory | Is the page builder current and inventoried? | Builder settings | Current version, valid licence, pages and templates listed | Update with a backup | Regenerating CSS or switching experiments without a backup | Medium | security | wp | elementor | authorized |
| INT-34 | Avada inventory | Is the theme builder current and inventoried? | Theme options | Current licensed version; a child theme; shortcode and custom code inventory | Update with a backup | The classic editor adds paragraph tags inside raw HTML blocks: edit in text mode | Medium | security | wp | avada | authorized |
| INT-35 | Sliders and heavy premium plugins | Are premium plugins licensed and current? | The plugins list | Current version with an active licence; sliders inventoried | Renew the licence or replace the plugin | Updating without a backup (sliders can come back empty) | High | security | wp | - | authorized |
| INT-36 | Forms and CRM integrations | Does every form reach its destination? | Form plugins and their integrations | Every form has a known destination and a successful test send; personal data is kept for a set time | Fix the destination | Forms wired to a CRM: test with the action neutralised or in the CRM sandbox, never with real data | High | security | all | forms | authorized |
| INT-37 | Caching plugins | Is there exactly one page cache layer? | Plugins and the host's cache | One page cache layer, with exclusions for pages with sessions or tokens | Keep one and configure the exclusions | Two layers that overwrite each other | Medium | security | wp | - | authorized |
| INT-38 | External account ownership | Does the owner control every external account? | Analytics, tag manager, search console, social and mail workspace accounts | Each account has a current owner, no former contractor keeps access, recovery and second factor are current | Transfer ownership and remove old access | - | High | security | all | - | authorized |
